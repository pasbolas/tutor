Heap insert, maxHeapify, and siftDown

A max heap is a complete binary tree where every parent is greater than or equal to its children. Therefore, the largest value is stored at the root.

Heap insert

heapInsert(H, value):
    H.size = H.size + 1
    i = H.size
    H[i] = value

    while i > 1 and H[parent(i)] < H[i]:
        swap H[i] and H[parent(i)]
        i = parent(i)

Recursive maxHeapify

maxHeapify(H, k):
    left = 2 * k
    right = 2 * k + 1
    largest = k

    if left <= H.size and H[left] > H[largest]:
        largest = left

    if right <= H.size and H[right] > H[largest]:
        largest = right

    if largest != k:
        swap H[k] and H[largest]
        maxHeapify(H, largest)

Iterative siftDown

siftDown(H, k):
    while k has at least one child:
        left = 2 * k
        right = 2 * k + 1
        largest = k

        if left <= H.size and H[left] > H[largest]:
            largest = left

        if right <= H.size and H[right] > H[largest]:
            largest = right

        if largest == k:
            break

        swap H[k] and H[largest]
        k = largest
OperationComplexityExam reason
InsertO(log n)The inserted value may move upward through the height of the heap.
maxHeapify / siftDownO(log n)The value may move downward through the height of the heap.
Build heapO(n)Heapify is applied from the last internal node back to the root.

Exam points

  • Insertion places the new item at the end, then restores heap order by moving upward.
  • siftDown starts at a node and repeatedly swaps it with the larger child if needed.
  • maxHeapify assumes the left and right subtrees are already valid heaps.
  • Duplicate values are allowed in a heap.

DFS timestamps and complexity

Depth-first search explores as far as possible along a path before backtracking. Discovery and finish times record when each vertex is first reached and when all its neighbours have been processed.

Main algorithm

DFS(G):
    time = 0

    for each vertex u in G.V:
        colour[u] = WHITE
        parent[u] = NIL

    for each vertex u in G.V:
        if colour[u] == WHITE:
            DFSVisit(G, u)

Recursive visit

DFSVisit(G, u):
    colour[u] = GREY
    time = time + 1
    discover[u] = time

    for each vertex v in Adj[u]:
        if colour[v] == WHITE:
            parent[v] = u
            DFSVisit(G, v)

    colour[u] = BLACK
    time = time + 1
    finish[u] = time
RepresentationComplexityExam reason
Adjacency listO(V + E)Each vertex is visited once and each edge is checked once.
Adjacency matrixO(V^2)Each vertex checks a full row of possible neighbours.

Exam points

  • WHITE means unvisited.
  • GREY means discovered but not finished.
  • BLACK means fully processed.
  • For a connected graph stored using adjacency lists, DFS runs in O(V + E).

Dijkstra table, relaxation, and complexity

Dijkstra's algorithm finds the shortest path from one source vertex to all other vertices in a weighted graph with non-negative edge weights.

Exam table columns

ColumnMeaning
VertexThe vertex currently being tracked.
DistanceThe best known distance from the source.
ParentThe previous vertex on the best known path.
Known / VisitedWhether the shortest distance has been finalised.

Relaxation

relax(u, v, weight):
    if dist[v] > dist[u] + weight(u, v):
        dist[v] = dist[u] + weight(u, v)
        parent[v] = u

Pseudocode

Dijkstra(G, source):
    for each vertex v in G.V:
        dist[v] = infinity
        parent[v] = NIL
        visited[v] = false

    dist[source] = 0
    Q = all vertices in G

    while Q is not empty:
        u = vertex in Q with smallest dist[u]
        remove u from Q
        visited[u] = true

        for each edge (u, v) in Adj[u]:
            if visited[v] == false:
                relax(u, v, weight)
ImplementationComplexityExam reason
Simple array / unsorted listO(V^2)Finding the minimum distance vertex costs O(V), repeated V times.
Binary heap priority queueO((V + E) log V)Priority queue updates and removals cost logarithmic time.

Exam points

  • The source distance starts at 0.
  • All other distances start at infinity.
  • The next selected vertex is the unvisited vertex with the smallest current distance.
  • Relaxation checks whether a better path to v exists through u.
  • Dijkstra is not valid for graphs with negative edge weights.

Prim compared with Dijkstra

Prim's algorithm constructs a minimum spanning tree. It is similar in shape to Dijkstra's algorithm, but the update rule is different.

Dijkstra

Chooses the next vertex using the smallest total distance from the source.

Prim

Chooses the next vertex using the cheapest edge connecting it to the current tree.

Prim pseudocode

Prim(G, start):
    for each vertex v in G.V:
        key[v] = infinity
        parent[v] = NIL
        inMST[v] = false

    key[start] = 0
    Q = all vertices in G

    while Q is not empty:
        u = vertex in Q with smallest key[u]
        remove u from Q
        inMST[u] = true

        for each edge (u, v) in Adj[u]:
            if v is in Q and weight(u, v) < key[v]:
                key[v] = weight(u, v)
                parent[v] = u

Key difference in the update rule

Dijkstra:
    if dist[v] > dist[u] + weight(u, v):
        dist[v] = dist[u] + weight(u, v)
        parent[v] = u

Prim:
    if weight(u, v) < key[v]:
        key[v] = weight(u, v)
        parent[v] = u
AlgorithmGoalUpdate rule
DijkstraShortest path treeUses total distance from the source: dist[u] + edge weight.
PrimMinimum spanning treeUses only the edge weight connecting the vertex to the tree.

Exam points

  • Prim does not calculate shortest paths from the start vertex.
  • Prim only cares about the cheapest edge that expands the tree.
  • Dijkstra gives shortest paths; Prim gives a minimum spanning tree.

Kruskal and Union-Find

Kruskal's algorithm constructs a minimum spanning tree by considering edges in increasing order of weight and adding an edge only if it does not create a cycle.

Kruskal pseudocode

Kruskal(G):
    MST = empty set

    for each vertex v in G.V:
        makeSet(v)

    sort all edges by increasing weight

    for each edge (u, v) in sorted edges:
        if find(u) != find(v):
            add edge (u, v) to MST
            union(u, v)

    return MST

Union-Find operations

makeSet(x):
    parent[x] = x
    rank[x] = 0

find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])
    return parent[x]

union(x, y):
    rootX = find(x)
    rootY = find(y)

    if rootX == rootY:
        return

    if rank[rootX] < rank[rootY]:
        parent[rootX] = rootY
    else if rank[rootX] > rank[rootY]:
        parent[rootY] = rootX
    else:
        parent[rootY] = rootX
        rank[rootX] = rank[rootX] + 1
StepComplexityExam reason
Sort edgesO(E log E)The edge list is sorted by increasing weight.
Union-Find checksAlmost O(1) eachPath compression and union by rank make operations very fast.
OverallO(E log E)Sorting dominates the running time.

Exam points

  • Sort edges from smallest weight to largest weight.
  • Add an edge only if its endpoints are in different sets.
  • If find(u) == find(v), adding the edge would create a cycle.
  • Union-Find is used to test connectivity efficiently.

Union-Find treeParent[] example

Union-Find stores disjoint sets. In a simple treeParent[] implementation, treeParent[x] stores the parent of x. A root is identified by treeParent[x] = x.

Simple implementation

makeSet(x):
    treeParent[x] = x

find(x):
    while treeParent[x] != x:
        x = treeParent[x]
    return x

union(x, y):
    rootX = find(x)
    rootY = find(y)

    if rootX != rootY:
        treeParent[rootY] = rootX

Worked example

Initial:
    treeParent[A] = A
    treeParent[B] = B
    treeParent[C] = C
    treeParent[D] = D

union(A, B):
    treeParent[B] = A

union(C, D):
    treeParent[D] = C

union(B, D):
    find(B) returns A
    find(D) returns C
    treeParent[C] = A
VertextreeParent[]Meaning
AAA is the root.
BAB is in A's set.
CAC is in A's set.
DCD reaches A through C.

Exam points

  • find(x) follows parent links until it reaches a root.
  • union(x, y) joins two different sets.
  • If two vertices have the same root, they are already connected.
  • Path compression makes future find operations faster by pointing nodes directly to the root.

BST and AVL trees

A binary search tree stores smaller values in the left subtree and larger values in the right subtree. An AVL tree is a binary search tree that keeps itself height-balanced using rotations.

BST search

BSTSearch(root, key):
    if root == NIL or root.value == key:
        return root

    if key < root.value:
        return BSTSearch(root.left, key)
    else:
        return BSTSearch(root.right, key)

BST insert

BSTInsert(root, value):
    if root == NIL:
        return new Node(value)

    if value < root.value:
        root.left = BSTInsert(root.left, value)
    else:
        root.right = BSTInsert(root.right, value)

    return root

AVL height and balance factor

height(node):
    if node == NIL:
        return 0
    return node.height

balanceFactor(node):
    return height(node.left) - height(node.right)

AVL rotations

rightRotate(y):
    x = y.left
    T2 = x.right

    x.right = y
    y.left = T2

    update height of y
    update height of x

    return x

leftRotate(x):
    y = x.right
    T2 = y.left

    y.left = x
    x.right = T2

    update height of x
    update height of y

    return y

AVL insert

AVLInsert(node, value):
    if node == NIL:
        return new Node(value)

    if value < node.value:
        node.left = AVLInsert(node.left, value)
    else if value > node.value:
        node.right = AVLInsert(node.right, value)
    else:
        return node

    update height of node
    balance = balanceFactor(node)

    if balance > 1 and value < node.left.value:
        return rightRotate(node)

    if balance < -1 and value > node.right.value:
        return leftRotate(node)

    if balance > 1 and value > node.left.value:
        node.left = leftRotate(node.left)
        return rightRotate(node)

    if balance < -1 and value < node.right.value:
        node.right = rightRotate(node.right)
        return leftRotate(node)

    return node
TreeSearchInsertWorst case
BSTO(h)O(h)O(n), if the tree becomes skewed.
AVLO(log n)O(log n)O(log n), because the tree remains balanced.

Exam points

  • BST rule: left subtree contains smaller values, right subtree contains larger values.
  • AVL balance factor must be -1, 0, or +1.
  • LL case uses a right rotation.
  • RR case uses a left rotation.
  • LR case uses a left rotation on the child, then a right rotation.
  • RL case uses a right rotation on the child, then a left rotation.

Final revision checklist

  • For heap questions, state whether the operation moves upward or downward.
  • For DFS questions, mention WHITE, GREY, BLACK and discovery/finish timestamps.
  • For Dijkstra questions, show distance, parent, and visited columns clearly.
  • For Prim questions, remember that the key value is the cheapest connecting edge, not total path distance.
  • For Kruskal questions, sort edges first and reject edges that create cycles.
  • For Union-Find questions, explain roots and parent links before giving the final array.
  • For AVL questions, identify the case first: LL, RR, LR, or RL.
