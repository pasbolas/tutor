# Q1(a) Disciplines associated with HCI

**Exam marker:** `S2`

### Core idea

Human Computer Interaction is interdisciplinary. It is not only computer science. HCI studies the interaction between people, technology, tasks, and the context in which systems are used. Multiple disciplines are needed because HCI must account for technical systems, human behaviour, physical abilities, social context, communication, and design.

### Disciplines associated with HCI

From the slides, the disciplines include:

- **Computer Science**
- **Psychology**
- **Sociology**
- **Anthropology**
- **Ergonomics**
- **Physiology**
- **Design**
- **Art**
- **Engineering**
- **Linguistics**
- **Philosophy**
- **Artificial Intelligence**

### How each discipline contributes

| Discipline | Contribution to HCI |
|---|---|
| Computer Science and Engineering | Faster machines, faster systems, and building better interfaces. |
| Psychology | Understanding the user as a thinking person, including perception, memory, learning, attention, and behaviour. |
| Sociology | Understanding group work, groupware, organisations, and social use of technology. |
| Anthropology | Understanding people in real contexts, cultures, practices, and environments. |
| Ergonomics | Matching equipment and interface design to human body shape, comfort, and physical use. |
| Physiology | Understanding physical capabilities and limitations of users. |
| Design | Interface layout, structure, interaction flow, and usability. |
| Art | Aesthetics, visual presentation, and making interfaces visually appropriate. |
| Linguistics | Language of commands, labels, prompts, and communication between user and system. |
| Philosophy | Contextual consistency, meaning, and reasoning about interaction. |
| Artificial Intelligence | Modelling the user in relation to software and intelligent systems. |

### Exam-ready explanation

HCI draws from several disciplines because designing interactive systems requires understanding both the technology and the humans using it. Computer science and engineering help build the system, psychology explains how users think and behave, sociology and anthropology explain social and cultural use, ergonomics and physiology deal with physical capabilities, while design, art, linguistics, philosophy, and AI contribute to layout, aesthetics, language, consistency, and user modelling.

# Q1(b) Human senses, Input / Output

**Exam marker:** `S2`

### Core idea

In HCI, humans receive output from systems and provide input back into systems through sensory and motor channels. Interface design must account for how users see, hear, touch, move, and physically interact with technology.

### Human senses in HCI

Information can be input or output as:

| Sense / channel | Meaning in HCI | Interface example |
|---|---|---|
| Visual | Seeing information | Text, icons, colours, charts, buttons, visual feedback. |
| Auditory | Hearing information | Alerts, speech output, notification sounds, screen reader audio. |
| Haptic | Touching and feeling, including awareness of physical interaction | Vibration feedback, touchscreens, physical buttons, force feedback. |
| Movement / positioning | Understanding position, movement, and bodily control | Mouse movement, gestures, controllers, motion sensors. |

### Input and output examples

#### Output from system to user

- Visual display on a screen.
- Sound notifications.
- Speech output.
- Haptic vibration.
- Tactile feedback in virtual environments.

#### Input from user to system

- Keyboard input.
- Mouse movement.
- Touch gestures.
- Voice commands.
- Eye tracking.
- Switch input.
- Movement sensors.

### Why this matters

Good interface design uses the right channels for the user and task. For example:

- A warning message should not rely only on colour because colour-blind users may miss it.
- A sound alert should not be the only feedback because deaf or hard-of-hearing users may not hear it.
- Buttons need enough size and spacing because users may have reduced dexterity.
- Screen reader users need content that can be understood without visual layout.

### Exam-ready explanation

Human senses are important in HCI because they are the channels through which users receive system output and provide input. Visual, auditory, haptic, and movement-based interaction all affect usability. Designers must choose suitable input and output methods for the user group, task, environment, and accessibility needs.

# Q1(c) Prototypes and types of prototypes

**Exam marker:** `S2 / R`

### Core idea

A prototype is an early version or representation of a product used to explore ideas, test design decisions, identify problems, and communicate the design before building the final system.

### Definition

Prototyping involves producing an early, inexpensive, scaled-down version of a product to reveal problems with the current design.

The slides describe prototypes as invaluable design tools for:

- Testing ideas.
- Clarifying requirements.
- Communicating with users and stakeholders.
- Evaluating usability concerns.
- Supporting iteration.

### Why prototypes are used

Prototypes help designers answer questions such as:

- Does the interface make sense to users?
- Can users complete the main tasks?
- Are navigation and interaction flows understandable?
- Are there missing requirements?
- Are the design assumptions wrong?

This final stage is important because users often respond differently to a prototype than designers expect.

### What to prototype

A prototype can explore:

- Screen layout.
- Navigation flow.
- Task sequences.
- Information architecture.
- Interaction controls.
- Visual design.
- System functionality.
- Usability concerns.

### Types of prototypes by fidelity

#### 1. Low-fidelity prototypes

Low-fidelity prototypes use a medium unlike the final product.

**Examples:**

- Paper sketches.
- Cardboard models.
- Post-it note interfaces.
- Storyboards.
- Wizard-of-Oz prototypes.
- Rough screen sequences.

**Advantages:**

- Quick to produce.
- Cheap.
- Easy to change.
- Encourages experimentation.
- Designers are more willing to discard them.
- Useful early in the design process.
- Good for focusing on high-level interaction and structure.

**Disadvantages:**

- Can be hard to represent detailed interaction.
- May not communicate navigation or flow well.
- Users may see them as unprofessional.
- Less realistic.
- Often requires a person to simulate system behaviour.

#### 2. Medium-fidelity prototypes

Medium-fidelity prototypes sit between rough sketches and a working system.

**Examples:**

- Wireframes.
- Clickable mockups.
- Screen mockups with partial navigation.
- Interactive design tools with limited functionality.

**Advantages:**

- More engaging than low-fidelity prototypes.
- Better at showing layout and flow.
- Still faster and cheaper than full development.

**Disadvantages:**

- May still lack realistic data and behaviour.
- Users may expect more functionality than exists.
- Can distract attention toward appearance rather than core interaction.

#### 3. High-fidelity prototypes

High-fidelity prototypes use materials or tools close to the final product. For software, a development environment or prototyping tool may be used.

**Examples:**

- Working software prototype.
- Clickable interface with realistic interactions.
- Prototype built in a specific development environment.
- Near-final UI simulation.

**Advantages:**

- More realistic.
- Allows realistic task evaluation.
- Can represent more screen and interaction detail.
- Better for communicating final design possibilities.
- User-driven testing is more natural.

**Disadvantages:**

- Takes more time and skill to build.
- More expensive than low-fidelity prototypes.
- Designers may become reluctant to change it.
- Users may think it is the finished system.
- Testers may focus on surface details instead of deeper design issues.

### Throw-away vs evolutionary prototyping

| Type | Meaning |
|---|---|
| Throw-away / rapid prototyping | Built to learn about requirements or design, then discarded. |
| Evolutionary prototyping | Prototype is developed further and may become part of the final system. |

### Exam-ready comparison table

| Prototype type | Best used for | Strength | Weakness |
|---|---|---|---|
| Low-fidelity | Early ideas, task flow, rough structure | Fast, cheap, easy to change | Low realism, limited interaction detail |
| Medium-fidelity | Wireframes and navigation | Good balance of speed and clarity | Still not fully realistic |
| High-fidelity | Detailed usability testing and stakeholder demos | Realistic tasks and interactions | Slow, costly, harder to discard |

# Q1(d) Human Centred Design

**Exam marker:** `S2 / R`

### Core idea

Human Centred Design is a design approach that starts with people, their needs, and their context, then develops solutions around those needs.

### Definition

Human-centred design is a creative approach to problem solving that starts with the people being designed for and ends with solutions purpose-built to suit their needs.

### Main features

Human-centred design involves:

- Building empathy with users.
- Understanding user needs and context.
- Generating ideas.
- Building prototypes.
- Sharing designs with users.
- Evaluating designs with users.
- Iterating throughout development.

### Principles of human-centred design

The slides identify these principles:

1. **Active involvement of users**
2. **Appropriate allocation of function between user and system**
3. **Iteration of design solutions**
4. **Multidisciplinary design teams**

### Essential activities in HCD / UCD

1. Understand and specify the context of use.
2. Specify user requirements and organisational requirements.
3. Produce design solutions, usually prototypes.
4. Evaluate designs with users against requirements.

### Human-centred design vs technology-driven design

| Human Centred Design | Technology Driven Design |
|---|---|
| Starts with users and their needs. | Starts with technology or technical possibility. |
| Focuses on suitability, usability, accessibility, and context. | Focuses on using latest technology to create innovation. |
| Requires user involvement and iteration. | May risk building something clever but unsuitable. |
| Measures success by how well the solution serves users. | Measures success by technical capability or novelty. |

### Why iteration matters

Designers rarely get the solution correct the first time. User feedback reveals issues in requirements, assumptions, language, layout, navigation, and task flow. Iteration lets the team correct these problems before final development.

### Exam-ready explanation

Human Centred Design focuses on understanding and meeting user needs. Users should be involved throughout the design and development process, and the design should be evaluated and improved through iteration. It differs from technology-driven design because the main focus is the user, not simply applying new technology.

# Q1(e) Universal Design and Irish equality legislation

**Exam marker:** `S2`

### Core idea

Universal Design means designing environments, products, services, and technologies so that they can be accessed, understood, and used by as many people as possible, regardless of age, size, ability, or disability.

### Definition from Irish legislation

Universal Design is:

> The design and composition of an environment so that it can be accessed, understood and used to the greatest extent possible by all people, regardless of their age, size or disability.

This definition is associated with the **Disability Act 2005** in the slides.

### Irish equality legislation point

The revision slides state that Irish equality legislation requires every person to be able to access goods and services on an equal basis with others.

Being able to access, understand, and use environments, technology, products, and services is linked to human rights such as:

- Being able to work.
- Receiving education.
- Accessing public services.
- Participating equally in society.

### Universal Design in Ireland

The slides state:

- In some countries Universal Design is called **Design for All** or **Inclusive Design**.
- Ireland contains a definition of Universal Design in legislation.
- Ireland has established a statutory **Centre for Excellence in Universal Design**.

### Universal Design is not just accessibility

Universal Design is related to accessibility, but it is not simply another word for accessibility.

| Accessibility | Universal Design |
|---|---|
| Often focuses on removing barriers for disabled users. | Designs for the widest possible range of people from the beginning. |
| May involve adaptations or separate features. | Aims to avoid segregating or stigmatising users. |
| Example: adding a ramp later. | Example: designing the entrance to be usable by everyone from the start. |

The slides note that accessibility features such as ramps and lifts can become symbols of separateness when they are treated as afterthoughts. Universal Design aims for equality of access from the beginning.

### Key drivers

- EU legislation is making accessibility expectations stronger for certain products.
- Universal Design is better design because it works first time for more people.
- Designing for everyone can reduce expensive and wasteful redesign later.

### Seven principles of Universal Design

| Principle | Meaning | Example |
|---|---|---|
| 1. Equitable use | Useful and marketable to people with diverse abilities. | A ramp usable by wheelchair users, people with buggies, and people with luggage. |
| 2. Flexibility in use | Accommodates a wide range of preferences and abilities. | Adjustable computer table height. |
| 3. Simple and intuitive | Easy to understand regardless of experience, knowledge, language, or concentration. | Clear icons with clear text labels. |
| 4. Perceptible information | Communicates necessary information effectively regardless of conditions or sensory ability. | Video with both audio and captions. |
| 5. Tolerance for error | Minimises hazards and negative consequences of accidental actions. | Undo feature in an app. |
| 6. Low physical effort | Can be used comfortably and efficiently with minimal fatigue. | Automatic door opener. |
| 7. Size and space for approach and use | Provides appropriate size and space regardless of body size, posture, or mobility. | Ticket machine screen usable from seated or standing position. |

### Accessibility guidelines by impairment type

#### Visual impairment

- Allow text resizing.
- Use good colour contrast.
- Test for colour blindness issues.
- Ensure the website works with screen readers.
- Use proper alternative text attributes.
- Do not autoplay sound.

#### Mobility and dexterity

- Do not assume everyone uses a mouse.
- Make the website keyboard accessible.
- Increase hit areas for links and buttons.

#### Cognitive needs

- Make location within the website clear.
- Organise content properly.
- Use clear headings.
- Make text scannable.
- Clearly mark links.
- Use images and graphics carefully to support meaning.
- Do not autoplay sound.

#### Auditory needs

- Provide captions and subtitles.
- Do not rely on sound alone.
- Do not autoplay sound.

### Exam-ready explanation

Universal Design means designing products, services, environments, and technologies so that they can be accessed, understood, and used by the widest possible range of people. In Ireland, the Disability Act 2005 defines Universal Design, and equality legislation requires equal access to goods and services. Universal Design is broader than accessibility because it aims to include diverse users from the start rather than adding separate adaptations later.

# Q1(f) Usability

**Exam marker:** `S2`

### Core idea

Usability describes how easy and effective a system is for humans to use. It is a major goal of interaction design.

### Definition

Usability can be defined as:

> The capacity to be used by humans easily and effectively.

Where:

- **Easily** means to a specified level of subjective assessment.
- **Effectively** means to a specified level of human performance.

### Main usability qualities

The slides link usability with:

- **Learnability**: how easy it is for new users to learn.
- **Efficiency**: how quickly users can complete tasks.
- **Memorability**: how easily users can return after time away.
- **Errors**: how many errors users make and how serious they are.
- **Satisfaction**: how pleasant or acceptable the system feels.

### Usability means the product should be

- Easy to learn.
- Effective to use.
- Enjoyable from the user's perspective.

### Guidelines, principles, and theories

| Term | Meaning |
|---|---|
| Guidelines | A basis for determining a course of action. |
| Principles | Basic rules that guide or influence thoughts or actions. |
| Theories | General principles that explain or predict facts or events. |

### Why usability matters

Poor usability can cause:

- User frustration.
- Errors.
- Slow task completion.
- Reduced trust.
- Higher training and support costs.
- Safety issues in critical systems.

### Measuring usability

Usability testing can measure:

- Number of errors.
- Time to complete tasks.
- Task completion rate.
- User satisfaction.
- User comments.
- Observed confusion or hesitation.

### Exam-ready explanation

Usability is about whether people can use a product easily and effectively. A usable interactive product should be easy to learn, efficient, memorable, error-tolerant, and satisfying. Usability can be evaluated by observing typical users performing realistic tasks and measuring errors, time, completion, and satisfaction.

# Q2(a) Accessibility / Usability for aging users

**Exam marker:** `S2`

### Core idea

Older users may experience sensory, physical, and cognitive changes that affect technology use. Design should support changing abilities without assuming that all older users are the same.

### Age-related impairments

The slides identify age-related changes in:

| Area | Possible issue |
|---|---|
| Sensory | Reduced vision and hearing. |
| Physical | Reduced mobility and manual dexterity. |
| Cognitive | Memory issues and reduced cognitive function. |
| Confidence | Loss of confidence using systems. |
| Orientation | Difficulty navigating and absorbing information. |

### Design implications

For older users, designers may need to:

- Simplify screen design.
- Use clear, linear navigation.
- Increase font size.
- Increase control size.
- Use high contrast.
- Reduce unnecessary memory load.
- Avoid clutter.
- Make interaction forgiving.
- Provide clear feedback.
- Support keyboard and alternative input.
- Test with real older users rather than assuming.

### Important caution

Do not assume all older users need the same design. The slides stress that aging is a process of **dynamic diversity**. Users differ widely in ability, confidence, experience, preferences, and technology familiarity.

The professor’s slide basically says: not all older people want giant fonts. Amazing how stereotypes keep failing as design methods.

### Classification of aging from slides

| Term | Age range / definition |
|---|---|
| Elderly | Over 65 years |
| Young Old | 65 to 74 years |
| Middle Aged Old | 70 to 80 years |
| Aged | Over 75 years |
| Chronically Old | Over 70 years |
| Oldest Old | 80 years and more |

### Studies mentioned in slides

The slides note that older users may:

- Search less efficiently on websites.
- Have more difficulty with tasks requiring three or more moves.
- Have more difficulty recalling previous moves.
- Have more difficulty remembering previously viewed information.

### What can be learned about older users and technology?

- Aging is dynamically diverse.
- Design must account for changing user characteristics.
- Flexibility is key.
- User-centred design is recommended.

### Exam-ready explanation

Accessibility and usability for aging users involves designing for possible changes in vision, hearing, mobility, dexterity, memory, confidence, and orientation. Designers should simplify interfaces, increase readability, provide clear feedback, reduce memory load, and allow flexible interaction. However, older users are diverse, so designers should avoid stereotypes and test with the actual target users.

# Q2(b) Persona(s)

**Exam marker:** `S2 / R`

### Core idea

A persona is a fictional but research-informed representation of a user group. It helps designers understand user goals, motivations, behaviours, and needs.

### Definition

A persona is a model of a user that focuses on the user’s goals when using the designed product.

Personas represent patterns of:

- User behaviour.
- Goals.
- Motives.
- Needs.
- Capabilities.
- Preferences.
- Contexts of use.

They often include made-up personal details to make the user feel more tangible and alive.

### What personas usually contain

A persona may include:

- Name.
- Photo or visual representation.
- Age.
- Occupation.
- Background.
- Technical skill level.
- Goals.
- Motivations.
- Needs.
- Frustrations.
- Behaviours.
- Context of use.
- Accessibility needs.
- Scenario of use.

### Personas vs user profiles

| Personas | User profiles |
|---|---|
| More like characters based on user research. | More general descriptions of user groups. |
| Focus on goals, motivations, behaviours, and context. | Often focus on demographic or statistical traits. |
| Help design teams discuss realistic users. | May be less vivid and less useful for design discussion. |

### Persona layers

The slides describe three layers for designing personas:

1. **Basic layer**: demographic and identifying information.
2. **Behaviour / needs layer**: goals, tasks, concerns, and motivations.
3. **Rich personal layer**: background, personality, context, and details that make the persona memorable.

### Exam-ready explanation

A persona is a fictional representation of a target user, based on patterns found in user research. It helps designers focus on user goals, motivations, needs, behaviours, and context. Personas are not meant to be random invented characters. They should represent real user patterns and support better design decisions.

# Q2(c) Personas in Design

**Exam marker:** `S2 / R`

### Why personas are used in design

Personas are useful in a human-centred design approach because they help teams understand and communicate user needs and requirements.

They are especially useful when designers:

- Cannot continuously access real end users.
- Need to communicate user research clearly.
- Need to test potential solutions conceptually.
- Need to keep user goals visible during design discussions.
- Need to represent different user groups.

### Benefits of using personas

The slides identify these benefits:

- More usable designs.
- More user-centred discussions.
- More effective communication in design teams.
- Stronger focus on users and their context.
- Helps team members discuss features from a user perspective.
- Turns user research into something memorable.
- Can highlight diversity and different user capabilities.
- Encourages empathy.
- Helps teams avoid designing only for themselves.

### Example of persona use in design discussion

Instead of asking:

- “Should we add this feature?”

A team can ask:

- “Would this persona need this feature?”
- “Would this persona understand this label?”
- “Would this persona be able to complete the task?”

This makes design discussion more user-focused and less like a room of developers worshipping their own buttons.

### Limitations of personas

The slides also give criticisms:

- Real user research and testing are preferable when possible.
- Personas may become weak if based on limited research.
- Personas may accidentally describe an “average” user rather than real diversity.
- Poor personas can reinforce assumptions instead of challenging them.
- Fictional details should not replace evidence.

### Good persona practice

Good personas should be:

- Based on user research where possible.
- Specific enough to guide design.
- Representative of actual user patterns.
- Focused on goals and behaviours, not only demographics.
- Used alongside real testing, not as a total replacement.

### Exam-ready explanation

Personas are used in design to keep user needs visible and communicate research findings across the design team. They can support decisions about features, navigation, language, and accessibility. Their benefits include more usable designs and better user-centred discussion, but they are limited if based on weak research or if they replace real user testing completely.

# Q2(d) Empathy Map

**Exam marker:** `S2`

### Core idea

An empathy map is a simple visual tool used to capture what is known about a user’s behaviours, attitudes, thoughts, feelings, and experiences.

### Definition

An empathy map is a simple, easy-to-digest visual that captures knowledge about a user’s behaviours and attitudes. It helps development teams better understand users.

### Common empathy map areas

The revision slides list these areas:

| Area | Question |
|---|---|
| Thinking | What might the user be thinking? What does this tell us about their beliefs? |
| Saying | What quotes or defining words did the user say? |
| Doing | What actions and behaviours were observed? |
| Feeling | What emotions might the user be feeling? |

Some empathy maps also include:

- Seeing.
- Hearing.
- Pains.
- Gains.
- Goals.
- Frustrations.

### Why empathy maps are used

Empathy maps help teams:

- Understand users more deeply.
- Build empathy for end users.
- Synthesise user research.
- Identify key insights.
- Connect personas to design decisions.
- Create a shared understanding across the team.
- Approach problems from the user’s point of view.

### When to use empathy maps

The slides say empathy maps are most useful:

- At the beginning of the design process.
- After user research.
- Before requirements and preliminary designs.

They can sometimes be created without new research if time is limited, using existing knowledge, existing personas, or stakeholder feedback. This is weaker, obviously, because guessing in a workshop is still guessing, even with sticky notes.

### Empathy maps and personas

Empathy maps can elaborate on user personas. A persona might describe who the user is, while an empathy map explores what the user thinks, says, does, and feels in a particular context.

### Exam-ready explanation

An empathy map is a collaborative visual tool used to understand a user’s behaviours, attitudes, thoughts, and feelings. It is normally created after user research and before detailed design. It helps teams synthesise observations, build empathy, and bridge the gap between personas and design decisions.

# Q3(a) Digital accessibility

**Exam marker:** `S2`

### Core idea

Digital accessibility means designing digital technologies so people with disabilities can use them equally and without barriers.

### Definition

Digital accessibility addresses discriminatory aspects related to equivalent user experience for people with disabilities.

It means people with disabilities can equally:

- Perceive technology.
- Understand technology.
- Navigate technology.
- Interact with technology and digital interfaces.
- Contribute without barriers.

### Examples of digital accessibility issues

| Barrier | Example |
|---|---|
| Visual | Text has poor contrast, images lack alternative text, screen reader cannot interpret content. |
| Auditory | Video has no captions, alerts rely only on sound. |
| Motor | Interface requires mouse precision, buttons are too small. |
| Cognitive | Navigation is confusing, text is dense, instructions are unclear. |

### Assistive and alternative input technologies

The revision slides mention:

#### Eye tracking

- Tracks eye movement.
- Uses gaze position to control the cursor.
- Dwelling on a location can trigger a click.
- Can be used with an on-screen keyboard.

#### Foot mouse

- One foot controls cursor movement.
- The other foot controls switches or click actions.

#### Voice recognition

- Allows control through speech.
- Useful for people who find typing difficult, painful, or impossible.
- Can support users with dyslexia by bypassing spelling/typing difficulties.

#### Switch input

- A button or sensor sends a signal to the computer.
- Can be triggered by reliable body movement, eye blink, or puff down a tube.
- Often used with scanning interfaces or on-screen keyboards.

#### Screen readers

- Software that reads screen content through synthetic speech or Braille.
- Useful for blind or visually impaired users.
- Works better when content structure, labels, headings, and alternative text are properly designed.

### Digital accessibility design practices

- Use semantic headings.
- Provide alt text for meaningful images.
- Ensure keyboard accessibility.
- Provide captions and transcripts.
- Use sufficient colour contrast.
- Do not rely on colour alone.
- Make controls large enough.
- Avoid autoplaying sound.
- Keep navigation predictable.
- Make forms clear and error messages helpful.

### Exam-ready explanation

Digital accessibility means ensuring that people with disabilities can perceive, understand, navigate, interact with, and contribute to digital technology equally. It involves removing barriers in visual, auditory, motor, and cognitive interaction. Designers should support assistive technologies such as screen readers, voice recognition, eye tracking, switch input, and keyboard navigation.

# Q3(b) Participatory Design

**Exam marker:** `S2`

### Core idea

Participatory Design involves end users and stakeholders directly in the design process.

### Definition

Participatory Design aims to create products or systems that are more usable, effective, and acceptable by incorporating users’ needs, preferences, and values into design.

### Who is involved?

- Designers.
- End users.
- Stakeholders.
- Project managers.
- Analysts.
- Developers.
- Other affected groups.

### Activities used in participatory design

The slides mention collaborative activities such as:

- Interviews.
- Surveys.
- Focus groups.
- Workshops.
- Prototyping sessions.
- Co-creation activities.
- Co-evaluation activities.

### Benefits

Participatory Design can lead to:

- Increased user satisfaction.
- Better understanding of users.
- Improved usability.
- Improved accessibility.
- Greater user engagement.
- Greater user ownership of the design.
- More innovative solutions.
- Better fit with real-world problems.
- More realistic expectations.

Participatory Design helps designers:

Participatory Design is an approach where end users and stakeholders actively contribute to design decisions. It uses collaborative methods such as interviews, surveys, workshops, focus groups, and prototyping. Its benefits include better user understanding, greater usability and accessibility, improved satisfaction, stronger ownership, and greater acceptance of the final product.

# Q3(c) Think Aloud evaluation

**Exam marker:** `S2`

### Core idea

Think Aloud is a usability evaluation method where participants verbalise their thoughts while using a system.

### Definition

In a thinking aloud evaluation, test participants use the system while continuously thinking out loud, meaning they verbalise their thoughts as they move through the user interface.

### What participants might say

Participants may verbalise:

- What they are trying to do.
- What they expect to happen.
- What confuses them.
- Why they clicked something.
- What they think a label means.
- What they notice on screen.
- Where they feel stuck.

### Why Think Aloud is useful

Think Aloud helps reveal:

- User expectations.
- Confusing labels.
- Incorrect assumptions.
- Navigation problems.
- Gaps between designer and user mental models.
- Reasons behind errors.
- Points where users hesitate.

### Facilitator role

The facilitator should:

- Give instructions.
- Encourage the user to keep talking.
- Avoid leading the participant.
- Avoid explaining the interface during the task.
- Ask follow-up questions carefully.
- Record observations and comments.

### Challenge for screen reader users

The slides specifically note that Think Aloud can be difficult for screen reader users because audio output from the screen reader may interfere with verbalising thoughts.

A solution is **retrospective Think Aloud**, where users complete the task first and then recount their thoughts afterwards.

### Exam-ready explanation

Think Aloud evaluation asks users to verbalise their thoughts while using an interface. It helps designers understand what users expect, where they become confused, and why usability problems occur. However, it may be difficult for screen reader users because screen reader audio can interfere with speaking, so retrospective Think Aloud may be used instead.

# Q3(d) Types of user research methods for a mobile app

**Exam marker:** `S2 / R`

### Core idea

User research methods help designers understand user behaviour, needs, problems, and context. For a mobile app, methods should be chosen based on research goals, available time, budget, accessibility needs, and the type of data required.

### Main research methods from the slides

The slides mention:

- Surveys.
- Interviews.
- Focus groups.
- Direct observation.
- Indirect observation.
- Diary studies.
- Activity traces / analytics.
- Usability testing.
- Prototyping sessions.

### Quantitative vs qualitative data

| Type | Meaning | Example |
|---|---|---|
| Quantitative | Data expressed as numbers. | Survey ratings, task time, completion rate, number of errors. |
| Qualitative | Data expressed as themes, patterns, stories, comments, and observations. | Interview quotes, observed frustration, usability notes. |

### Method 1: Interviews

#### Description

Interviews ask users about their experiences, needs, frustrations, and perceptions.

#### Types

| Type | Meaning |
|---|---|
| Structured | Tightly scripted, replicable, but less rich. |
| Semi-structured | Guided by questions but allows deeper exploration. Good balance. |
| Unstructured | Open and flexible, rich but less replicable. |

#### Advantages

- Rich qualitative information.
- Good for understanding perceptions and experiences.
- Allows follow-up questions.
- Useful for exploring accessibility barriers in depth.

#### Disadvantages

- Time-consuming.
- Resource intensive.
- Users may not remember or explain important parts of experience accurately.
- Poor questions can bias answers.

#### Good mobile app use

Use interviews to understand why users struggle with login, navigation, accessibility settings, notifications, or completing tasks on the app.

### Method 2: Surveys / questionnaires

#### Description

Surveys gather responses from a larger number of users, often using rating scales or structured questions.

#### Advantages

- Good for demographic data.
- Good for quantitative information.
- Can reach many users.
- Cheaper and faster than many interviews.

#### Disadvantages

- Data quality may be weak.
- Users may misunderstand questions.
- Less depth than interviews.
- Closed questions can restrict answers.

#### Good mobile app use

Use surveys to measure how common certain issues are, such as difficulty reading text, finding features, or completing checkout.

### Method 3: Observation

#### Description

Observation involves watching users interact with the app in real or controlled settings.

#### Types

| Type | Meaning |
|---|---|
| Direct observation | Watching users perform tasks directly. |
| Indirect observation | Using diary studies, logs, analytics, or activity traces. |

#### Advantages

- Captures actual behaviour, not just what users claim.
- Reveals tacit knowledge.
- Can collect qualitative and quantitative data.
- Useful for task timing, task completion, and errors.

#### Disadvantages

- Time-consuming.
- Resource intensive.
- Analysis can take longer.
- Participants may behave differently while observed.
- Tasks and prompts must not bias participants.

#### Good mobile app use

Observe users completing realistic tasks such as registering, changing settings, searching, booking, buying, or using accessibility features.

### Method 4: Focus groups

#### Description

A focus group gathers several participants to discuss experiences, needs, expectations, and reactions.

#### Advantages

- Good for gathering multiple opinions quickly.
- Can reveal shared concerns.
- Useful early in design.

#### Disadvantages

- Dominant participants may influence others.
- Not ideal for measuring actual usability.
- People may say socially acceptable things rather than honest things.

#### Good mobile app use

Use focus groups to explore expectations, pain points, and initial reactions to app ideas before prototyping.

### Method 5: Diary studies

#### Description

Users record their experiences over time while using the app in real life.

#### Advantages

- Captures real-world use over time.
- Useful for apps used repeatedly or in different contexts.
- Reveals patterns not visible in one test session.

#### Disadvantages

- Depends on participant effort.
- Data may be incomplete.
- Takes longer.

#### Good mobile app use

Use diary studies for apps involving routines, health tracking, transport, shopping, study, or communication.

### Method 6: Analytics / activity traces

#### Description

System logs or analytics show how users move through the app.

#### Advantages

- Quantitative.
- Can involve large numbers of users.
- Shows drop-off points and common paths.

#### Disadvantages

- Does not explain why users behave that way.
- Privacy and consent must be handled carefully.
- Can miss accessibility issues not visible in logs.

#### Good mobile app use

Use analytics to identify where users abandon registration, fail payments, or stop using a feature.

### Method 7: Usability testing

#### Description

Typical users perform realistic tasks while the researcher observes performance.

#### Measures

- Task completion.
- Time taken.
- Number of errors.
- Assistance needed.
- Satisfaction.
- Comments.

#### Advantages

- Directly tests whether the mobile app is usable.
- Reveals problems in navigation, labels, layout, and interaction.
- Can use prototypes or working apps.

#### Disadvantages

- Requires careful participant recruitment.
- Can be time-consuming.
- Small samples may not represent all users.

### Recruitment strategy

Participants should represent target users. For a mobile app, recruitment may consider:

- Current users.
- Potential users.
- Competitor app users.
- Accessibility needs.
- Age range.
- Technical proficiency.
- Device type.
- Different stakeholder groups.

### Ethical considerations

The slides highlight:

- Informed consent.
- Careful handling of personal information.
- Avoiding bias.
- Ethical data recording.
- Explaining what data will be collected.
- Handling qualitative data such as recordings, transcripts, quotes.
- Handling quantitative data such as survey responses, task timings, and task completions.

### Exam-ready answer structure for a mobile app question

If asked to propose research methods for a mobile app, answer like this:

1. **Define the study goal**: for example, identify accessibility barriers and usability issues.
2. **Use interviews** to collect rich user experiences and understand barriers.
3. **Use surveys** to gather broader quantitative data from more users.
4. **Use observation or usability testing** to see actual behaviour while users complete realistic tasks.
5. **Use diary studies or analytics** if the app is used repeatedly over time.
6. **Recruit realistic participants**, including users with relevant accessibility needs.
7. **Address ethics**, including consent, privacy, recording, and avoiding bias.

# Q4(a) Affordance

**Exam marker:** `S2 / R`

### Core idea

Affordance is about what an object or interface suggests users can do with it.

### Definition

The slides describe affordance as a central concept of the ecological approach to perception. It is the “readiness to hand” that makes websites, interfaces, and gadgets physically easier to use.

When the affordance of an object is perceptually obvious, users can easily know how to interact with it. When it is not obvious, users are more likely to make mistakes.

### Interface affordance examples

| Object | Affords |
|---|---|
| Button | Pressing / clicking. |
| Scrollbar | Dragging up or down. |
| Text field | Typing. |
| Slider | Dragging left/right or up/down. |
| Door handle | Pulling or pushing, depending on shape. |
| Underlined text link | Clicking / tapping. |

### Affordance in UI design

Good affordance means:

- Buttons look clickable.
- Links look like links.
- Controls visually suggest their function.
- Drag handles look draggable.
- Users do not need to guess what an element does.

Poor affordance means:

- Clickable things look like plain text.
- Buttons look disabled when they are active.
- Icons are unclear.
- Controls do not behave as expected.
- Users make errors because the interface “lies” visually.

### Perceptual affordance

Perceptual affordance means the user can perceive the possible action directly from the object’s appearance. For example, a raised button visually suggests pressing.

### Exam-ready explanation

Affordance refers to the actions that an object or interface suggests to the user. In HCI, good affordance helps users know how to interact with interface elements without needing instructions. A button should look pressable, a scrollbar should look draggable, and a link should look clickable. Poor affordance causes mistakes because users cannot tell what actions are possible.

# Q4(b) Mental models with examples

**Exam marker:** `S2 / R`

### Core idea

A mental model is the user’s internal understanding of how something works or how to use it.

### Definition

The slides describe mental models as:

- Internal constructions of some aspect of the external world that allow predictions to be made.
- The expectations a person has about how things work.
- A dynamic mental representation built from experience and instruction.

### Why mental models matter

Users rely on mental models to:

- Decide what to do next.
- Predict what will happen.
- Understand new systems.
- Make inferences in complex situations.
- Use prior experience with unfamiliar interfaces.

### Types of mental model

| Type | Meaning | Example |
|---|---|---|
| Structural model | Understanding how a system works internally. | Knowing that a thermostat switches heating on/off based on temperature. |
| Functional model | Understanding how to use the system. | Knowing which button to press to increase the desired temperature. |

### Mental models in HCI

Users develop knowledge of:

- How to use the system.
- What to do next.
- To a lesser extent, how the system works.

Designers often have more detailed mental models of their own systems. This can create a gap between designer mental models and user mental models.

### Erroneous mental models

Users sometimes form incorrect mental models.

#### Example 1: Thermostat

A person comes home to a cold house and sets the thermostat to the highest temperature, believing the house will heat faster. This is incorrect because the heating does not warm faster at a higher setting. It simply heats until it reaches the selected temperature.

#### Example 2: Pedestrian crossing button

A user repeatedly presses the button believing more presses will make the lights change faster. Usually, extra presses do nothing.

#### Example 3: Frozen cursor

A user presses many random keys when the cursor freezes, assuming this might fix it. This shows uncertainty about how the system works.

#### Example 4: Television

A user hits the television to make it work or stop pixelating. This is an example of an inaccurate mental model because the action usually has no meaningful effect on the system.

### Mental models and metaphors

A metaphor presents a new concept through a familiar real-world framework.

Examples:

- Desktop metaphor: files and folders on a screen.
- Shopping basket/cart in e-commerce.
- Trash/recycle bin for deleting files.

Metaphors help users transfer existing knowledge to unfamiliar systems. However, they can also mislead users if the system does not behave like the real-world object.

### Designer vs user mental models

One major usability issue is the gap between what designers think is obvious and what users understand. Designers know too much about their own system, so they may believe features are easy to understand. Users often have incomplete or inaccurate mental models, making mistakes more likely.

### Exam-ready explanation

A mental model is the user’s internal understanding or expectation of how a system works. Users use mental models to predict outcomes and decide what to do. Mental models may be incomplete or wrong, such as believing a thermostat heats faster when set to maximum. Designers should align interfaces with users’ likely mental models and avoid assuming users understand the system as deeply as designers do.

# Q4(c) Gestalt Laws with an example for each

**Exam marker:** `S2 / R`

### Core idea

Gestalt laws explain how humans organise visual information into meaningful groups and patterns. They matter in interface design because users perceive layouts as grouped structures rather than isolated screen elements.

### Gestalt means

The slides state that Gestalt means shape, usually a shape made from more than one part. Gestalt laws are innate laws of perception.

### Main Gestalt laws from the slides

#### 1. Proximity

**Meaning:**

Elements placed close together are perceived as related or belonging to the same group.

**Interface example:**

A label placed close to a text box is understood as belonging to that input field.

**Slide example:**

Dots or interface elements close together appear as groups rather than random clusters.

#### 2. Similarity

**Meaning:**

Elements with similar shape, colour, size, or orientation are perceived as belonging together.

**Interface example:**

Buttons with the same colour and style are seen as part of the same action group.

**Slide example:**

Elements of the same shape or colour are seen as connected.

#### 3. Closure

**Meaning:**

People mentally fill in missing parts of a shape to perceive a complete object.

**Interface example:**

A logo or icon may use incomplete outlines, but users still perceive the intended shape.

**Slide example:**

Missing parts of a circle are filled in mentally so that it appears as a whole circle.

#### 4. Continuity

**Meaning:**

People prefer to perceive smooth, continuous lines or paths rather than disconnected pieces.

**Interface example:**

A step-by-step progress indicator uses aligned steps to imply a continuous process.

**Slide example:**

A set of dots may be perceived as two crossing lines rather than random dots.

#### 5. Symmetry

**Meaning:**

Symmetrical regions tend to be perceived as coherent figures. Symmetry creates stability and order.

**Interface example:**

A balanced card layout or symmetrical navigation area feels like a coherent section.

**Slide example:**

Regions bounded by symmetrical borders are perceived as coherent shapes.

### Why Gestalt laws matter in UI design

Gestalt laws help designers:

- Group related controls.
- Make layouts easier to scan.
- Reduce visual confusion.
- Support recognition.
- Create clear structure.
- Make interfaces easier to understand quickly.

### Exam-ready table

| Gestalt law | Meaning | Example |
|---|---|---|
| Proximity | Close things are seen as related. | Label placed beside its input field. |
| Similarity | Similar-looking things are grouped. | Same-coloured buttons suggest same category. |
| Closure | Missing parts are mentally filled in. | Incomplete logo still perceived as a full shape. |
| Continuity | Eyes follow smooth paths. | Progress steps arranged in a line. |
| Symmetry | Symmetrical areas are perceived as coherent. | Balanced card layout appears organised. |

### Exam-ready explanation

Gestalt laws describe how humans organise visual information. In HCI, they help designers create clear layouts by grouping related items, making controls recognisable, and reducing visual confusion. Proximity groups nearby items, similarity groups visually similar items, closure fills missing shapes, continuity follows smooth paths, and symmetry creates coherent figures.

# Q4(d) Nielsen's 10 heuristics with examples

**Exam marker:** `S2 / R`

### Core idea

Nielsen’s heuristics are ten usability principles used to evaluate interface design. They are often used as a checklist in heuristic evaluation.

### Heuristic evaluation

Heuristic evaluation is a process where experts assess the usability of interfaces through independent walkthroughs and report issues. Evaluators use established heuristics to identify usability problems early in development.

### Nielsen's 10 heuristics

#### 1. Visibility of system status

**Meaning:**

The system should keep users informed about what is going on through timely and appropriate feedback.

**Examples:**

- Loading spinner.
- Progress bar.
- Confirmation message after saving.
- Highlighting selected items.

**Exam example:**

A website should make it obvious where the user is, what they can do, where an action will take them, and where they have been.

#### 2. Match between system and the real world

**Meaning:**

The system should speak the user’s language and use real-world conventions.

**Examples:**

- Use “basket” or “cart” in shopping apps.
- Use familiar date and time formats.
- Avoid technical database terms in user-facing screens.

**Slide point:**

Use mapping: the relationship between controls, their movements, and real-world results should make sense.

#### 3. User control and freedom

**Meaning:**

Users need clear ways to escape unwanted states and undo actions.

**Examples:**

- Back button.
- Cancel button.
- Undo.
- Home button.
- Stop/end action.

**Slide point:**

A page needs a clearly marked “emergency exit.”

#### 4. Consistency and standards

**Meaning:**

Users should not have to wonder whether different words, actions, or situations mean the same thing.

**Examples:**

- Same button style for same action type.
- Standard link colours.
- Platform conventions.
- Consistent navigation.

**Internal consistency:** same behaviour within one system.

**External consistency:** same behaviour across systems or devices.

#### 5. Error prevention

**Meaning:**

Design should prevent errors from happening where possible.

**Examples:**

- Disable submit until required fields are filled.
- Confirm before deleting.
- Use input validation.
- Provide constraints on date fields.

**Exam point:**

Ask whether the system prevents serious errors and allows easy recovery if they occur.

#### 6. Recognition rather than recall

**Meaning:**

Make objects, actions, and options visible so users do not need to remember information from one part of the interface to another.

**Examples:**

- Visible menu options.
- Icons with labels.
- Recent searches.
- Autocomplete suggestions.

**Slide point:**

This heuristic relates to affordance and system status.

#### 7. Flexibility and efficiency of use

**Meaning:**

The system should support both novice and expert users.

**Examples:**

- Keyboard shortcuts.
- Search commands.
- Customisable workflows.
- Tab navigation in spreadsheets.

#### 8. Aesthetic and minimalist design

**Meaning:**

Interfaces should not contain irrelevant or rarely needed information. Extra information competes with important content.

**Examples:**

- Clean forms.
- Remove unnecessary text.
- Progressive disclosure.
- Avoid cluttered dashboards.

#### 9. Help users recognise, diagnose, and recover from errors

**Meaning:**

Error messages should use plain language, describe the problem, and suggest a solution.

**Examples:**

- “Your password must include at least 8 characters” instead of “Invalid input.”
- Highlight the field with the error.
- Place cursor at the first error.
- Keep user-entered data after an error.

**Slide error-handling points:**

- Detect errors immediately.
- Maintain the item in error.
- Visually highlight the problem field.
- Display error messages on screen.
- Use auditory signals conservatively.

#### 10. Help and documentation

**Meaning:**

Help information should be easy to search, concrete, and task-focused.

**Examples:**

- Searchable help centre.
- Step-by-step instructions.
- Tooltips.
- FAQs.
- Contextual help.

### Full exam table

| No. | Heuristic | Meaning | Example |
|---|---|---|---|
| 1 | Visibility of system status | Keep users informed. | Loading bar after upload. |
| 2 | Match with real world | Use user language and real conventions. | Shopping cart icon. |
| 3 | User control and freedom | Provide exits and undo. | Cancel button. |
| 4 | Consistency and standards | Same actions and terms mean same things. | Standard navigation style. |
| 5 | Error prevention | Stop errors before they happen. | Confirm delete. |
| 6 | Recognition rather than recall | Make options visible. | Menu items visible instead of commands memorised. |
| 7 | Flexibility and efficiency | Support novices and experts. | Keyboard shortcuts. |
| 8 | Aesthetic and minimalist design | Remove irrelevant clutter. | Clean checkout form. |
| 9 | Error recovery | Help users understand and fix errors. | Clear form validation message. |
| 10 | Help and documentation | Provide searchable, concrete help. | Step-by-step help page. |

### Exam-ready explanation

Nielsen’s heuristics are ten usability principles used to evaluate interfaces. They help identify problems such as poor feedback, confusing language, lack of user control, inconsistency, weak error prevention, excessive memory load, poor support for expert users, clutter, unclear error messages, and missing help. Designers can use them as a checklist to find and fix usability issues.
