01 What are functions in SQL

Functions are pre-built pieces of functionality you can run against your data quickly, without writing the logic yourself. They let you perform calculations, modify individual values, format dates and numbers for display, convert a column from one data type to another, or manipulate output across a group of rows.

SQL functions sometimes take arguments, and always return a value. SQL comes with a long built-in list of them, and they fall into two broad categories:

  • Single-row functions — act on each row returned by the query, returning one result per row.
  • Multiple-row (group) functions — act on a whole set of rows, returning one result per group of rows. These are covered in a later lesson.

This lesson is about single-row functions. Their features:

  • They act on each row the query returns, and return one result per row.
  • The value they return can be a different data type to the one they were given.
  • They can take one or more arguments, and an argument can be a user-supplied constant, a column name, or an expression.
  • They can be used in a SELECT, WHERE, or ORDER BY clause.
  • They can be nested inside one another.

05 lpad( ) and rpad( )

LPAD and RPAD pad a string on the left or right with a chosen character, until it reaches a target length. They're mostly used to format data consistently, e.g. lining up codes to the same width.

07 NULLs and concatenation

Be careful with || and NULLs: if either side of a || is NULL, the whole result becomes NULL.

CONCAT( ) instead just skips any NULL argument, keeping the rest. Since we usually want to keep whatever isn't NULL, CONCAT( ) is the safer default.
