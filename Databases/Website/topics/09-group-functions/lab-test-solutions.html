Question 1:

In an ERD, a weak entity depends on a parent entity because:

A. It stores its own primary key

B. It has no attributes

C. Its existence depends on a related entity through a foreign key

D. It always has many-to-many relationships

Correct answer: C

Explanation: A weak entity requires a foreign key from a parent table for identification.

Question 2:

Which relationship type best describes “A department employs many instructors, but each instructor works in only one department?

A. 1:1

B. 1:N

C. N:M

D. 0:1

Correct answer: B

Explanation: One department → many instructors (one-to-many).

Question 3:

In the DDL below, which constraint enforces domain integrity?

A. PRIMARY KEY

B. FOREIGN KEY

C. CURRENT_TIMESTAMP

D. NOT NULL

Correct answer: D

Explanation: Domain integrity ensures that the values in a column are valid according to their domain (type, allowed values, or constraints like NOT NULL). NOT NULL enforces domain integrity, because it restricts which values are allowed (no NULLs) for that column..

Explanation: RIGHT JOIN keeps all rows from the right table; left-side unmatched columns become NULL.

Question 15:

Match each type of integrity with the mechanism that enforces it:

A. Entity Integrity

B. Referential Integrity

C. Domain Integrity

List of Mechanisms:

  1. Ensured by defining valid data types, NOT NULL, CHECK, and DEFAULT constraints
  2. Ensured by primary keys that uniquely identify rows and cannot be NULL
  3. Ensured by foreign keys linking parent and child tables

Correct matches:

A → 2

B → 3

C → 1

Explanation:

Entity integrity = unique rows (PRIMARY KEY); referential integrity = valid relationships (FOREIGN KEY); domain integrity = valid values (data types, CHECKs, defaults).

Question 18:

A well-designed data model should ensure data consistency, minimal redundancy, and flexibility.

Which combination of design principles below most directly supports these goals?

A.

Use surrogate keys instead of natural keys, denormalise tables for speed, and allow NULLs everywhere.

B.

Use meaningful primary keys, establish relationships through foreign keys, and apply appropriate constraints.

C.

Avoid constraints to allow data freedom, store repeated attributes across entities, and use wide tables for all data.

D.

Rely on triggers and scripts to correct data after entry rather than defining constraints at design time.

Correct answer: B

Explanation:

Entity, referential, and domain integrity rely on keys and constraints. Designing relationships and applying constraints at the schema level ensures consistency and non-redundancy.

Question 19:

During the logical to physical modelling stage, a many-to-many relationship between students and courses is resolved by introducing a junction (weak) entity enrolment.

Which of the following correctly explains why this step is required?

A.

Because it reduces the number of tables by merging both entities into one.

B.

Because every course must have only one student, and every student must enrol in exactly one course.

C.

Adding a weak entity allows each university to store multiple grades in one cell without requiring normalisation.

D.

Because relational databases cannot directly represent many-to-many relationships and must decompose them into two one-to-many relationships.

Correct answer: D

Explanation:

DBMSs can only model one-to-many and one-to-one directly. An junction table resolves many-to-many links by storing both foreign keys, maintaining referential integrity.
